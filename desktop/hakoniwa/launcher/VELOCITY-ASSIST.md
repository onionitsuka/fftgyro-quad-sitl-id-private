# 推定速度アシスト

研究の荷重モデルから推定した水平速度で、手動操縦を補助する実験モード。
位置を保持するモードではない。推定が偏れば、スティック中央でも機体が流れる。
実機や論文のモデル係数は変更しない。

## 操作

1. `python3 desktop.py launch hakoniwa --assist aero` で起動する。
2. QGCの再接続とReady for takeoffを待つ。プロポの **Position** ボタンを押す。
   このモードに限り、Position要求を **Offboard** に切り替える。QGCの表示もOffboardになる。
3. いつものArm操作を行う。スロットルを中央より上へ動かすと上昇する。
4. 前後・左右スティックは水平速度、中央は速度ゼロの指令。
   高度方向も速度指令で、スロットル中央は上昇・下降を止める指令。
5. 通常のLand/Disarm操作で終了する。Stabilizedへの切り替えも保持している。
   Stabilizedではスロットルの意味が推力操作に変わる。

水平速度の指令上限は2 m/s（斜めも同じ）、上下1 m/s、Yaw45°/s。
スティック中央の8%を不感帯とした。速度の**指令**上限であり、実速度の制限ではない。
QGCのジョイスティック校正・ボタン割り当ては変更しない。自動Armはしない。

通常のGPS付きシミュレーションへ戻すには **「箱庭・研究モデル」** を開く。
**「箱庭・IMU積分アシスト（比較用）」** は空力モデルによる速度修正を外した比較モード。
切り替え時は新しいセッションになり、機体も初期位置へ戻る。
「箱庭を再起動」は選択したモードを保持する。

## 操縦者による水平速度の零点補正

InterLink DXの **ボタン0（QGCのボタン表示で確認）** を押す。
QGCでは未割り当てのボタンで、Arm=9、Disarm=10、Position=2、Stabilized=1は変更しない。
物理ボタンの印字名との対応は未確認。バックエンドがLinuxのjoystick入力を直接読むため、
QGC側で新しいアクションを割り当てる必要はない。

操縦者が目視で地面に対して止まっていると判断したとき、押した瞬間の水平推定速度を
偏りとして保存する。その後は `制御へ渡す水平速度 = 元の推定速度 − 保存した偏り` とする。
元のIMU・空力推定器は動き続ける。補正値はNED座標で保持し、方位変更で回転させない。
鉛直速度、姿勢、目標速度、荷重モデルの係数は変更しない。

押すたびに保存値を置き換える。押しっぱなしでは1回だけ処理し、USB接続時の初期状態では
作動しない。着陸・Disarmで補正を解除する。採用時にはQGCへ
`Pilot zero: horizontal speed reset` を送信し、ODOMETRYのreset_counterを進める。
これは操縦者による「対地速度ゼロ」という観測で、シミュレータの正解速度は使わない。

動いているときに押すと、その速度を偏りにしてしまう。押した後にスティックを中央へ戻して
挙動を見る。一定の偏りを補正する機能であり、変化する風・姿勢誤差・推定誤差まで消える
保証はない。無操作時の実際の漂流量の改善は、操縦者による試運転で確認する。

## データの流れ

```text
プロポ → QGC → 目標速度 ──────────────────────┐
                                              ↓
模擬IMU・RPM → 速度推定 → 操縦者の零点補正 → PX4の速度推定・制御 → 姿勢制御 → モーター → 模擬機体
                   ↑                                            │
             研究の荷重モデル                         模擬センサへ戻る

模擬機体の真の位置・速度 → Unity表示と評価ログだけ
模擬気圧計＋IMU → 鉛直速度推定 → PX4 → 高度方向の制御
```

アシストではHIL_GPSとHIL_STATE_QUATERNIONを送らず、GPS融合も無効にする。
水平位置の観測は与えない。機体の真の姿勢も推定器へ渡さない。
IMUは機体重心に置いた理想センサを基本とし、250 Hzの信号を区間平均して50 Hzで積分する。
初期Roll/Pitchは停止中の加速度、初期Yawは0。その後は角速度で姿勢を進める。
磁気・気圧はPX4側の姿勢・高度推定で使用する。

5 Hzで直近0.2秒のIMU・RPM平均を使い、計測比力×質量とモデルの力の差から
水平速度を修正する。中心差分0.02 m/s、正則化0.25、修正時定数0.5秒、
ゲイン適用前の1回の修正上限2 m/s。離陸判定後7秒と、いずれかのローターが
3500 rpm未満の区間ではモデル修正を行わない。範囲外の流入ではIMU積分を保持する。
推定器は実測RPM経路の保存係数、模擬機体は通常は推算RPM経路の保存係数を使う。
ここでのRPMはどちらもシミュレーション生成値で、実機の実測値ではない。

元のオフライン推定を、そのまま再現したものではない。
今回は因果的な移動平均、水平2成分の空力修正、気圧・IMUによる鉛直速度を使う。
鉛直はIMUで速度と位置を進め、気圧高度との誤差を時定数0.5秒の二次の観測器で修正する。
PX4から出力された速度は推定器へ戻さない。
着陸時にはPX4の着陸判定で静止更新する。また水平推定のドリフトが着陸判定を妨げる場合に備え、
「気圧センサから求めた高度が離陸地点の±0.25 m、回転数二乗で求めた推力が重量の65%未満、角速度0.15 rad/s未満、
比力の大きさが重力加速度の±0.5 m/s²」を0.5秒満たすと静止と仮定する。
これは平坦な地面へ戻る試験向けの仮定で、機体の真の接地情報は使わない。

PX4への受け渡しには外部速度観測のODOMETRYを使う。位置・姿勢の欄はNaN。
EV_CTRL=4で速度だけを融合し、3方向の速度分散を0.25 (m/s)²とする。
推定にはPX4と同じIMU・気圧信号を使うため、
独立センサ融合としての共分散の厳密性を主張しない。これは操縦補助の接続実験である。
手動入力が0.5秒途絶えたら、Arm中のOffboard指令送信を止め、PX4の既存フェイルセーフへ渡す。

## 比較とログ

各セッションの `velocity-assist.csv` に真の速度、推定速度、目標速度、修正回数、
修正を止めた理由、PX4のモードを保存する。
元の水平推定速度、零点補正値、ボタン補正の回数、ODOMETRY reset_counterも保存する。
`research-flight.csv` は位置・姿勢・RPM・指令・6軸荷重、
`research-manifest.json` は係数の版・選択モード・密度・風・バイアスを保存する。
真値は評価と表示にのみ使い、推定器へ戻さない。

条件の指定例（シミュレータ専用）:

```bash
python3 desktop.py launch hakoniwa --assist aero
python3 desktop.py launch hakoniwa --assist imu
# 同じ一定加速度バイアスを模擬IMUとPX4へ与える例
python3 desktop.py launch hakoniwa --assist aero --accel-bias 0.03 0 0
# 推定器に知らせない風。推定器が返す量は対地速度とは一致しなくなる
python3 desktop.py launch hakoniwa --assist aero --wind-ned 1 0 0
```

基本設定のIMUには一定バイアスもランダムノイズもない。
この理想条件ではIMU積分だけの方が良い場合もある。違いを見るには、同じバイアス・風・
操作条件で比較する必要がある。推定の偏りを「操縦者なら容易に補正できる」とはまだ言えない。
模擬機体と推定器が同じ研究に由来するので、ここで操縦できても実機での有効性の証明にはならない。

## 初版の動作確認（2026-11-12、3d48b48）

隔離したPX4インスタンス10で離陸・前後操作・着陸・自動Disarmを確認した。
GPS融合と位置観測が無効、外部速度と気圧高度が有効であることを3つのEKFすべてで確認した。
Unityが書き返した位置と箱庭時計も確認した。7件の単体試験と保存力学の120状態の照合を通過。
詳細は 研究室で保存した検査記録（2026年11月12日）。

この無風・理想IMUの試運転では、飛行中の水平速度誤差のRMSEは0.309 m/s。
中央操作を1秒以上続けた区間でも、真の水平速度のRMSは0.326 m/sだった。
位置を止めるには操縦者の補正が必要であり、その操作のしやすさはまだ確認していない。

## 着陸後の再Arm

2026-11-12の対話セッションでは、PX4内蔵の模擬バッテリー情報が更新されず、
着陸後に `Battery unhealthy` で再Armを拒否する事象があった。電圧や残量の不足ではなく、
記録の時刻が古くなったことによる拒否だった。同時に `system_power` の更新停止も観測した。
PX4の定期処理が止まる根本原因は未特定で、PX4本体には修正を加えていない。

研究モデルでは内蔵の時間放電モデルを使わず、力学側のセンサループから
モーターモデルと同じ4S電圧を5 Hzで送る方式にした。電圧はセッション中一定で、
電池の消耗はモデル化していない。QGCの残量表示はセル電圧3.5〜4.2 Vに対する概算。
バッテリーの鮮度・低残量のチェック、着陸後のDisarmと利用者による再Armは維持する。
連続離着陸の検査は `verify_rearm.py`（隔離したインスタンス10限定）で実行できる。

再Armの検査中、2回目はPX4の高度が5.27 mまで増えた一方、力学上の上昇は0.052 mに
留まる不整合も見つかった。旧版の鉛直速度欄はPX4自身の推定値で、観測分散も10⁶と大きく、
EKFが速度を初期化する際にもその分散が使われていた。鉛直速度を気圧・IMUから直接推定し、
有限の分散で渡す構成へ変更した。検査もPX4の高度表示だけでなく、模擬機体の真の上昇量を
必須条件にした。

修正後は同じセッションで2回の離陸・着陸・自動Disarmを通過した。
真の最高高度は0.782 mと0.688 m、PX4の表示は0.776 mと0.708 mだった。
両着陸後のバッテリー更新の遅れは0.20秒以下で、system_powerの更新も継続していた。
研究室で保存した連続離着陸の検査記録（2026年11月12日）。
着陸でDisarmした後は、利用者が改めてArm操作を行い、スロットルを中央より上へ動かす。
